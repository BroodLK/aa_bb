{% translate "1. What Counterintelligence is and why it exists" %}

{% blocktrans trimmed %} Counterintelligence (CI) helps officers find members whose behaviour around fleets matches the patterns of a spy: listening in on comms without flying, dropping off comms or logging off just before a fight, keeping alts in hostile entities, sharing voice identities, or repeatedly knowing about operations that turned out to be leaked. {% endblocktrans %}

{% blocktrans trimmed %} It does this by lining up data the alliance already has (AFAT fleet rosters, Mumble and Discord presence, zKillboard killmails, in-game login/logoff times from corptools, and Big Brother's own checks) on a single timeline per operation, then running a set of detectors over it. {% endblocktrans %}

{% translate "Findings are leads, not verdicts." %} {% blocktrans trimmed %} Every detector has innocent explanations: scouts, cyno alts, people going to bed, a bad internet connection. Each finding shows the evidence it is based on so an officer can judge it. Never act against a member on a finding alone; talk to them, check the evidence, and record your decision in the case. Keep CI information to people with CI permissions. {% endblocktrans %}

{% translate "5. Getting fleets in" %}
{% translate "Automatically from AFAT" %}

{% blocktrans trimmed %} Every AFAT FAT link becomes an operation with its roster. Nothing needs doing; it appears under Operations within a minute or two. Duplicate operations with the same name close together are merged, but two different AFAT fleets are never merged even if they share a name. {% endblocktrans %}

{% translate "By hand: New Operation" %}

{% blocktrans trimmed %} For briefings, strategic ops or fleets not run through AFAT, a manager can click New Operation on the Operations page and give it a name, type, secrecy level, start time and optional end time. Leave the end time blank while the fleet is running and close it later. {% endblocktrans %}

{% translate "9. Leaked operations" %}

{% blocktrans trimmed %} When hostiles were clearly forewarned (waiting on the target grid, forming a counter before the ping, a structure timer suddenly defended), a manager should click Mark Leaked on the operation and write down why. {% endblocktrans %}

{% blocktrans trimmed with pre=pre_window_minutes %} A member "knew about" an operation if they were on its roster, or were in comms between its disclosure time (or {{ pre }} minutes before the start, if no disclosure time is set) and its start. {% endblocktrans %}

{% blocktrans trimmed with days=leak_lookback_days ops=leak_min_ops rate=leak_min_rate_pct lift=leak_min_lift %} Looking back {{ days }} days, a member is flagged only when at least {{ ops }} operations are marked leaked, they knew about at least {{ ops }} of them and at least {{ rate }}% of all leaked ones, and they knew about leaked operations at least {{ lift }}× as often as about clean ones. {% endblocktrans %}

{% translate "Example." %} {% blocktrans trimmed %} Of 8 operations, 3 were marked leaked. Pilot A was in comms for all 3 leaked ones and none of the 5 clean ones, and is flagged. Pilot B attends everything (all 8), so their attendance says nothing and they are not flagged. {% endblocktrans %}
  • {% translate "A single leak can never identify anyone; it takes several." %}
  • {% translate "Only mark leaks you are confident about. Each wrong mark adds noise for everyone who attended." %}
  • {% translate "Clear Leak removes the mark and its findings; all numbers are recalculated in the background." %}

{% translate "13. Known limitations" %}
  1. {% translate "Comms means “on the Mumble server”, not “in the fleet channel”." %} {% translate "Mumble data usually carries no channel, so comms-based findings are capped." %}
  2. {% translate "In-game login/logoff is coarse." %} {% translate "Only the latest value at each corptools refresh is seen; short sessions in between are missed." %}
  3. {% translate "Support pilots rarely appear on killmails." %} {% translate "Logi, scouts and ECM get a low “no combat” mark unless objectives list their roles." %}
  4. {% translate "Leak detection depends on managers marking leaks" %} {% translate "and only becomes reliable after several leaked and clean operations." %}
  5. {% translate "AFAT operations start as Standard secrecy," %} {% translate "so the briefing and sensitive-operation checks only run once a manager raises the level." %}
  6. {% translate "One case per member per operation." %} {% translate "A flagged member attending many sensitive operations gets several cases." %}
  7. {% translate "Thresholds are starting points," %} {% translate "not calibrated on real data yet." %}
{% translate "14. Troubleshooting" %}
{% translate "No Mumble data appears" %}
{% translate "Check that MUMBLE_AUTHENTICATOR_LOG_PATH is set and the file is readable by the Celery worker (mounted into its container if you use Docker). The worker log says so if it is not." %}
{% translate "An operation stays “Active”" %}
{% translate "AFAT has not reported the fleet as closed (clickable FAT links never close). Use Close Fleet, or Edit Operation to set the end time." %}
{% translate "“Pending zKillboard scan” or scan incomplete" %}
{% translate "The scan runs 30 minutes after the window closes and retries automatically when zKillboard rate-limits it. Managers can force it with the rescan button." %}
{% translate "No killmails on an older operation" %}
{% translate "zKillboard only allows looking back 7 days, so operations older than that cannot be scanned." %}
{% translate "AFAT keeps changing my times" %}
{% translate "It cannot once you have edited the window (“Manual window” badge)." %}
{% translate "The same fleet appears twice" %}
{% translate "Use Deduplicate Fleets on the Operations page." %}
{% translate "A finding looks wrong" %}
{% blocktrans trimmed with days=auto_override_days %}Check the evidence on the case. If it is genuinely noise, dismiss it; that member is exempt from those finding types for {{ days }} days.{% endblocktrans %}
